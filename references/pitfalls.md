# 整理文件时踩过的坑

动手前扫一遍。每条都是真实遇到过的。

## 1. 路径写死的东西，挪了就静默坏掉

| 会写死路径的地方 | 怎么查 | 处理 |
|---|---|---|
| launchd 定时任务 | `ls ~/Library/LaunchAgents/`，读每个 plist 的 `ProgramArguments` / `WorkingDirectory` / `StandardOutPath` | 目录不动；或搬走后在旧路径留替身：`ln -s 新路径 旧路径`。README 里加粗"路径写死，不要再挪" |
| 别的项目的 `.env` / 脚本硬编码 | 在相关项目里 grep 目录名 | 同上 |
| Python 虚拟环境（`.venv`、`.ppt-venv`） | 目录里有 `bin/activate`、`pyvenv.cfg` | 不挪（venv 里记录着绝对路径，挪了就失效） |
| 应用托管的工作区：Codex App 的 `~/Documents/Codex/<日期>/<会话>/{outputs,work}` | 结构规整、按日期分 | 先问用户：原地建索引，还是并进对应项目。并走后 App 回看旧会话会找不到文件，要在汇报里说明；空会话夹（outputs/work 都空）留在原地即可 |
| iCloud 同步夹被别的程序当落盘点（如 `iCloud/AI日报/`） | 项目代码或记忆里有写 | 不动 |
| git 仓库 | 有 `.git` | 整个搬没问题；往里加子夹只是多几个未跟踪文件，无害 |

从日志判断一个 launchd 任务是不是活的：plist 里写的 `StandardOutPath` 文件如果从来没被创建过，说明任务从没跑过。

## 2. 云盘

- iCloud Drive 在本机的路径是 `~/Library/Mobile Documents/com~apple~CloudDocs/`。
- 从云盘 `mv` 到本地 = 云端不再保留，手机 / iPad 上看不到——先问用户。用户说"云盘的就在云盘里整理"，就在云盘内部建同样的结构（`mv` 在同一容器内只是改名，不触发下载）。
- 云盘根目录可能有指向本机桌面/文稿的替身（`Desktop -> /Users/xxx/Desktop`），别把它们当文件夹搬。

## 3. 文件名

- URL 编码的名字（`%E5%85%B3%E4%BA%8E...pdf`、`2024%e5%b9%b4...zip`）解码后改成中文名再放：`%E5%85%B3`=关、`%e5%b9%b4`=年、`%e4%b8%8a`=上、`%e4%b8%8b`=下。改名等于移动，允许；README 里写一句"原文件名是 URL 编码"。
- 名字里有 `=`、`[`、`*`、连续空格、`|`、全角引号的文件，长命令容易被权限系统拦或被 shell 误解析：单独一条命令、双引号包全路径；实在过不去就把那一条命令交给用户点一下运行，别硬试十次。
- Word 留下的 `~$xxx.docx/pdf`（一两百字节）是临时锁文件，没用；不删（原则），随文件夹一起搬，README 里说"可以自己删"。
- 数字编号的下载夹（查重 / AIGC 报告常见：`2026060808185641292977/`）改成 `2026-06-08_查重报告全套/` 这种可读名。
- 同名不同大小的文件是不同版本，两份都要留（一份进 `重复副本/`），README 里注明大小 / 日期不同。

## 4. 系统 / 软件残留，默认不动

`.DS_Store`、`.localized`、`desktop.ini`、`$RECYCLE.BIN`（Windows 迁过来的）、`.Doubao` 之类 App 配置夹、`Photos Library.photoslibrary`、`JianyingPro/`、游戏存档（`Kingdom Rush Vengeance/`）。它们不是用户的"文件"，搬了只会添乱；README 里点一句就好。

## 5. 别按文件名猜内容

`微信图片_2026xxxx.jpg` 可能是录用通知单，也可能是豆瓣短评截图；`IMG_0215.PNG` 可能是论文批注也可能是随手截的文章。看一眼（Read 图片）再归类，30 秒的事，归错了用户以后找不到。

## 6. 权限 / 工具层面的现实

- 有些环境下 `mv`、`ln`、`find -exec`、脚本执行会被安全分类器拦；简单的 `mkdir -p` / `mv 绝对路径 绝对路径` 通常能过。所以：分小批、绝对路径、加引号；一次一组同类文件。
- 家目录 / 外接盘（`/Volumes`）可能没有访问权限：明说没检查，不要假装看过。
- 建不成替身链接（`ln -s`）时，把那一条命令给用户，并在 README 里写清楚为什么需要它。

## 7. 边界不清就问，但一次问完

问的时候给 2–3 个选项 + 推荐项，用户点一下就行。典型的边界问题：
- 桌面上另一个人 / 另一件事的材料要不要收？（例：女朋友的论文文献 vs 用户自己的毕业论文）
- 应用托管的工作区怎么处理？
- 安装包 / 工具目录算不算？
- 云盘的搬本地还是就地整理？

问完就按答案做，不要再自己发挥；用户后来改主意（"我说的是整个电脑"）就按新范围补做，前面做过的不用推翻。
